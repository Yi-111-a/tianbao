# 《天宝》开发计划

> 首个剧本：天宝十载（751），玩家扮演唐玄宗，目标是在 755 年冬之前消弭安史之乱，或在乱起后守住长安。
> 依据：[剧本大纲](scenarios/TIANBAO_751_OUTLINE.md)、[酒馆调研](research/SILLYTAVERN_NOTES.md)、[概念图](../design/concepts/PROMPTS.md)、[差评分析](REVIEW_ANALYSIS.md)。
> 工期按「Claude 会话 + Codex 子代理」的实际工作日估算，只作排期参考。

## 0. 定位

- **一句话**：盛唐书案上的帝王模拟。LLM 负责扮演群臣和撰写史笔；国库、兵马、人心由确定性引擎结算，每一条诏令都有执行回执。
- **三个差异点**：
  1. **门面**：唐风「御案」实物化界面，所有美术原创。
  2. **可信**：数字只来自引擎，叙事只陈述已执行的事实，存档可以悔棋、分叉。
  3. **随处可玩**：本地运行；可以接任意 OpenAI 兼容模型；也可以在 Claude Code / Codex 里直接下旨游玩，不需要另外的 API key。

## 2. 阶段计划

### 阶段 1：定美术方向（1–2 天）

- **定稿**：从概念图里选定主界面方案（A：平铺舆图；B：斜放书案并配势力绸带）。
- **修正问题**：
  - 去掉龙纹，唐代帝王服饰不用龙纹团补。
  - 舆图改为唐代疆域，去掉现代海岸线和日本、台湾的轮廓。
  - 文字统一用简体。
- **产出 `design/STYLE_GUIDE.md`**：
  - 色板 token：石青、石绿、赭石、朱砂、泥金、黄麻纸色。
  - 字体：霞鹜文楷、思源宋体，都是开源字体。
  - 纹样：宝相花、卷草纹。
  - 按钮形制：墨块、朱印、卷轴。
- **原则**：正式素材一律**不带文字**，所有文字由前端渲染。概念图里的字只用来看构图。
- **验收**：你确认风格稿，并确认 3 张高保真主界面图。

### 阶段 2：引擎补 P0 机制（5–7 天）

**剧本侧**（剧本大纲 §8 的 P0）：
1. 条件 DSL 扩展：回合区间、人物状态和属性、兵力、谁任某官。
2. 事件抉择真正生效：事件挂起后由玩家选择；超时执行默认项。
3. 兼职：`Character.offices`，并在场景里配置兼职上限。
4. 结局与失败判定：在 `scenario.yaml` 里声明 `endings` / `fail_states`，每季末判定一次。
5. 军队扩展：加 `commander` / `loyal_to` / `quality` 字段，新增 `adjust_army` / `set_army_faction` 两种操作。
6. 计数器与旗标年龄，用于「连续两季国库为零」这类条件。

**提示词侧**（酒馆调研的 P0）：
7. 统一的 `PromptBlock` 和装配函数 `assemble()`，带预算控制。
8. 引擎生成的「事实摘要」块：数字全部来自 `WorldState`，预算紧张时也不能被裁掉。
9. 人物卡扩展：示例对话、开场白、历史后提醒、深度提醒、发言权重、分情绪立绘。
10. 史料条目 `lore/*.yaml`：用关键词激活；按引擎状态设条件 `when`；用 `known_by` 限定谁知道这条史料。
11. 提示词检视：每次调用都记下用了哪些块、多少 token、有没有被裁掉。

- **验收**：每项都有单测；Mock 模式下跑完 23 季不报错；回放校验的 `state_hash` 一致。

### 阶段 3：天宝剧本落地（5–7 天，可与阶段 2 后半并行）

- **YAML**：按大纲把 scenario / characters（约 20 人）/ regions（22 区）/ armies / events（约 25 个）/ memorial_items（前三季的教程）写成 YAML。
- **史实核对**：大纲里标了 [待核实] 的条目，对照《资治通鉴》卷 216–217、《旧唐书》《新唐书》本传逐条核对。核实不了的明确标为游戏虚构。
- **平衡**：用 CLI 跑种子批量模拟（套用 balance-and-replay-testing 技能），确认 6 种结局都能达成、不玩也会走向历史结局、正常发挥的胜率合理。
- **P1 机制**：人物心态模型（野心、畏惧、恩宠）、情报迷雾（隐藏数值只显示区间）、谏言库。
- **验收**：`sim validate` 通过；跑 1000 局得到结局分布报告；教程三季可以完整走通。

### 阶段 4：美术量产（2–3 天，主要是 Codex 的生成时间）

- **流水线**：给 `sim gen-assets` 加一个 `codex` 提供方，读 `assets.yaml` 中的提示词和统一画风前缀，生成后转成 webp，把 hash、尺寸、提示词、生成时间写回清单。最多 3 路并行。
- **清单**（约 70 张，按每张 1 分钟、3 路并行估算，约 30–40 分钟，另加重试）：

  | 类别 | 数量 | 说明 |
  |---|---|---|
  | 人物立绘 | 约 20 + 8 | 8 张是铠甲版或起兵后版 |
  | 事件插画 | 14 | |
  | 结局图 | 6 | |
  | 标题长卷 | 1 | |
  | 书案场景 | 2 | |
  | UI 纹理与图标 | 约 15 | 宣纸、黄麻纸、卷轴、墨块、印章、资源图标 |

- **一致性**：同一人物的不同版本用首张立绘作参考图（`codex exec -i`）。分情绪立绘放到 P1。
- **舆图**：AI 画不准地理。先用公开数据画出唐代疆域和区域的矢量底稿，再让 Codex 按底稿做「绢本设色」风格化；区域边界由前端用 SVG 叠加。数据来源和许可证要先确认。
- **验收**：清单全部生成并校验通过；你逐张过目，标出需要重画的。

### 阶段 5：前端重做（8–10 天）

- **技术**：保留 React + Vite；加 Framer Motion 做动效；样式全部走设计 token；目标分辨率 1920×1080，可缩放到 1366。
- **界面**：

  | 界面 | 要点 |
  |---|---|
  | 标题页 | 长卷缓慢平移，配书法标题 |
  | 主界面 | 书案、舆图、实物入口 |
  | 资源栏 | 悬停显示收支明细，每一项都标明来源 |
  | 舆图图层 | 节度辖区、民心、兵力、漕运、危机烽燧 |
  | 奏疏 | 奏疏条目卡片，每条附大臣建议，可一键采纳 |
  | 召对 | 流式输出；划选大臣原话存入谏言库；立绘随情绪切换 |
  | 廷议 | 发言人和立场由引擎决定；结论存入谏言库 |
  | 诏书 | 预览逐条显示执行回执，再盖印颁布 |
  | 推演结果卷 | 逐条显示已执行、驳回或延误，数字变化附原因，配事件插画 |
  | 事件抉择 | |
  | 结局 | 结局画面，生成可分享的《本纪》长图 |
  | 存档时间线 | 悔棋、分叉 |
  | 设置 | 模型路由、用量和费用 |

- **验收**：每个界面截图和概念图逐一对比；没有 API key 时 Mock 能完整通关；暗部和色彩在常见显示器上都清楚可读。

### 阶段 6：在 Claude Code / Codex 里直接玩（3–5 天）

- **MCP 服务 `sim mcp`**（stdio），和网页共用同一个存档目录。提供的工具：开局/读档、看奏疏、召对、廷议、拟诏（提交操作并返回回执）、确认、推进回合、查账和查舆图。
- **两种模式**：
  - **客户端模型即内阁**：由 Claude Code / Codex 自己的模型扮演群臣、解释诏令，所以不需要 API key。工具只返回事实摘要和人设，引擎仍然负责校验和结算。
  - **游戏自带模型**：客户端只负责传话。
- **分发**：Claude Code 插件（一个「上朝」技能加 `.mcp.json`）；Codex 用 `codex mcp add` 加 AGENTS.md。
- **观战**：终端里下旨，浏览器里实时显示舆图和立绘。
- **验收**：在 Claude Code 和 Codex 里各玩通教程三季，存档能在网页里打开。

### 阶段 7：试玩与打磨（持续）

- **多模型实测**：用 DeepSeek、Qwen、GLM、Claude 各跑一遍，记录每回合的延迟、token 和费用，在设置页给出推荐的路由方案。
- **常见问题回归**：大臣说错数字、死人开口、诏令被曲解，每类问题都补一个测试用例。
- **新手引导**：每回合由首辅提醒最急的三件事；提供短局（20 季）和长局两种模式；难度用「历史引力」调节，分演义、史实、地狱三档。

### 阶段 8：发布

- 发布本地网页版和一键启动脚本（Windows 用 .bat，macOS 用 .command）；README 附截图和动图。桌面封装（Tauri）放到后续再定。
- 发布前要处理 GitHub 历史中的逆向文档，确认许可证，确认字体和数据来源的授权。

## 3. 关键风险

| 风险 | 应对 |
|---|---|
| 图里的文字和地理不准 | 正式素材不带文字；舆图走「矢量底稿 + 风格化」 |
| 画风或人物前后不一致 | 统一画风前缀，用参考图，逐张人工过目 |
| Codex 额度和速度 | 最多 3 路并行；清单驱动，失败只重试一次；可切换到其他图像提供方 |
| LLM 延迟和费用 | 按角色分配模型（摘要用小模型）；流式输出；结构化调用不流式；没有模型时用 Mock 兜底 |
| 史实错误 | [待核实] 清单逐条查证；虚构内容明确标注 |
| 与原作撞脸 | 改用唐代视觉体系，美术全部原创，不使用原作的任何素材或文案 |
| 酒馆是 AGPL 许可 | 只借鉴思路和格式，不复制代码 |
