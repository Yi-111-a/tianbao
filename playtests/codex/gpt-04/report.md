## 具体问题、证据与影响

### 1. 廷议把颜真卿与李林甫的具体主张倒置【确认的说明矛盾，优先修复】

季节：天宝十载冬 T3。

工具与参数：
```json
{"tool":"court_debate","memorial_id":"t3_review","participants":["yan_zhenqing","li_linfu","gao_lishi"]}
```

同季 briefing：
- 颜真卿赞成考课严明，原话“请黜其尤者以儆百官”。
- 李林甫反对骤加黜陟，原话“臣恐……人人自危”。
- 选项 strict 为“严加黜陟”，lenient 为“依例考课，不另究”。

court_debate 却返回：
- 颜真卿“赞成……主张 lenient（与所上之言相合）”。
- 李林甫“反对……主张 strict，反对 lenient（与所上之言相合）”。
- 最后统计依例考课获颜真卿、高力士支持。

这不是玩家改变人设，而是工具把“赞成／反对议题”错误映射到具体选项。本人依工具要求扮演了它指定的立场，并在对话中指出矛盾；实际诏令仍选择 strict。

建议：每条奏疏谏言显式绑定 option_id；廷议复用该绑定，不以 support/oppose 猜测主张哪个选项。对 strict/lenient 这类相反选项建立一致性检查。

### 2. 易帅回执称旧军改由副将暂摄，实际仍保留原统帅【确认的状态与回执不一致，优先修复】

相关操作：
- T7：`ops=[{"op":"set_army_commander","army":"jinjun","character":"gao_xianzhi"}]`，高仙芝统禁军。
- T16：`p_an_capital → detain`，高仙芝改统范阳军并赴镇。

T16 draft_edict、confirm_edict 均写：
“范阳军由高仙芝统领……其原统京师禁军改由副将暂摄。”

但 T17 audience(an_lushan) 的事实摘要仍写禁军统帅高仙芝，且将其赴范阳行程描述为禁军“统帅未到任”。于是另查：
```json
{"tool":"op_reference","entity_kind":"armies","ids":["jinjun","fanyang_army"]}
```
返回两军的 commander 都是 `gao_xianzhi`。T18 audience(yan_zhenqing) 仍写“京师禁军64000……统帅高仙芝不在军中，副将暂摄”。

“人不在军中、由副将暂摄”本身可以成立；问题在于回执说已退出原军指挥关系，实体表却继续保留双重 commander，且行程目标是范阳，不是禁军驻地京畿。全程没有再给高仙芝重新兼统禁军的命令。

建议：明确“撤销统帅”和“仍遥领但副将暂摄”的区别，确保回执、实体数据和 audience 使用同一状态；人物赴别镇途中，不应显示为向原军赴任。

### 3. 同一任命回执先说“不赴任”，紧接着又说“已启程赴任”【表达歧义，未据此认定最终状态错误】

- T1 choose 河东择帅：先称李光弼任河东节度、“遥领，不赴任（今在河西）”，紧接着称河东军易帅、“已启程赴任……约2季抵河东”。
- T6 `t6_jiannan → exile`：先称国忠任剑南节度“遥领，不赴任”，随后称统剑南军并启程。
- T16 `p_an_capital → detain`：高仙芝亦先被描述为“遥领，不赴任”，随后启程。

这可以由选项内多个 op 先后执行解释；后续实际到达也有事实确认。但“遥领、不赴任”是很强的最终态表述，玩家容易以为诏令互相打架。

建议：把同一选项的任命、易帅、出发合并成最终态摘要，例如“已授节度并兼统该军，赴任中；到任前副将暂摄”，必要时另列逐条技术回执。

### 4. 解镇后立即解锁善后奏疏，需要同季再读 briefing 才看得到【重要流程可发现性问题】

T16 第一次 confirm_edict 完成 `p_an_capital → detain` 后，我在 end_turn 前再次调用 briefing，才看到新出现的：
- `p_fanyang_warn` 范阳旧部可虑。
- `t16_court_detained` 政事堂议·范阳善后。

其中 p_fanyang_warn 明确说明：安抚不足时旧部可能兵变，三策以上可保无虞；新帅到镇且安抚足够才会兵柄归零。因此同季追加 `all_three` 很关键。第一次确认回执没有显式提醒“新增善后奏疏，结束回合前可继续下诏”。

本局已通过同季重读、追加诏令解决，没有发生兵变或卡住。但严格照“读简报→拟诏→确认→结束”的单次循环，容易错过风险管理窗口。

建议：confirm_edict 返回 new_memorials、new_choices 和“本季尚可行动”提示；对关键解锁提醒再次查看 briefing。

### 5. 同季两份政事堂议均可获得同类收益【机制边界需说明】

T16 先采纳 `t16_court → attend`，获得朝争 −3、君威 +1；解镇后新出现 `t16_court_detained`，又可采纳 attend，获得同样效果。本局两项都执行。

建议：明确这是两次不同会议，或将这类亲临调停收益设为本季共享，避免后续反复切换状态刷收益。

### 8. 扩军后经常军费、军粮未见随之变化【平衡与经济模型疑问】

T7 京畿募兵 +8000，T14 又募宿卫 +6000，均实际执行；相应后续对账仍列边镇军费 −165、京师禄米军粮 −125，未见新增宿卫经常支出项目。军费另有剧本项“边费岁增 −35”，与上述募兵的对应关系没有解释。

不能仅凭本局证明内部完全不按兵力计费；但就可见经济反馈，新增军力主要是一次性成本，后续养兵负担不清楚。

建议：说明哪些支出为固定额、哪些随兵额变化；若刻意简化经济模型，在选项旁注明后续成本已包含于固定军费。

建议：将旧职置于履历，当前头衔、开场与官职随状态更新；旧职不应成为现任自称。

### 10. 终局复盘“要事”漏掉决定胜局的到镇、归心【确认的复盘覆盖不足】

建议：终局复盘保留胜负判定直接相关事件，再展示其他要事；若有条数截断，应展示截断提示或链接完整历史。

### 11. 改革与调停的反馈较机械【主观机制意见】

实际例子：
- T9 罢荔枝驿送：君威 +2、民心 +2，同时朝争 +2。
- 多次 `p_court_harmony → mediate`：朝争 −5、国库 −80、积弊 +1。
- 清吏、裁外戚、严制举多次附带朝争增加，而且明示不会自行回落。

这些代价都事先写明，不是隐藏惩罚。但连续游玩后，容易形成“改革积朝争→定期花钱赐宴→积弊回升”的固定循环，调停对象也不具体。T6 已让国忠久镇剑南，T16 议事和记忆仍主要围绕国忠参与政事堂；远程奏疏可以解释，但叙述没有区分书面上言与在场争执。

建议：让朝争更具体地绑定人物、派系、实际官职与所在；不同改革触发不同阻力，调停也明确对象与长效条件，减少重复按钮。

### 12. 风闻、取整与延期说明的阅读负担【说明改进项】

本局危机区间会变化，工具同时返回“本次实际漂移区间”和“下次预计漂移”，需要仔细区分。没有把风闻区间中心变化当作真实数值变化，也没有据此声称发生数字造假。公开对账中的少量“取整差”有明确列示，未发现可确认的加总矛盾。

“delayed 下季执行／预计第N回合结算”最终均按时执行，但“下季”容易让人误以为还要多等待一个完整决策季。

建议：把“当前确认即生效”“下一次 end_turn 结算执行”“之后某季到达”分开显示；把上季实际与下季预计做成清楚的并列表格。

## 本地工具问题与修复

以下发生于调用工具或保存报告阶段，不属于 tianbao 引擎故障，也不影响会话结果：

1. 开局工具发现时，第一次按 tianbao 名称过滤没有列出工具；扩大查询后获得了工具元信息，但输出过大，被标记为截断。随后改用 `mcp__tianbao__` 前缀，只输出各工具的参数声明，恢复正常。没有因此错过 list_scenarios→new_game 的开局顺序。
2. 终局后更新本地日志时，apply_patch 在同一补丁中同时 Delete File 和 Add File 指向 `tool-log.json`，返回：
   `apply_patch verification failed: invalid patch: multiple operations target ...\\tool-log.json`。
   原因是日志保存补丁写法错误。改用一次 Add File 写入 `tianbao-tool-log.json`，已成功；游戏未受影响，也没有重复任何游戏操作。这一错误只出现一次，未触发连续三次换方案的规则。

优先修复廷议选项绑定，以及易帅后的真实 commander 与回执一致性；它们会直接误导政治判断和军队部署。其次补充确认诏令后的新奏疏提示、部分调兵的准确语义、经常账目说明和关键终局事件复盘。最后再改善头衔更新、远程议事表现与改革阻力的差异化。
